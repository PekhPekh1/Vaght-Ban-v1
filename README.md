# وقت‌بان — سامانه مدیریت حضور و غیاب و حقوق

سامانه یکپارچه مدیریت پرسنل با رابط کاملاً فارسی (راست‌به‌چپ، تقویم شمسی جلالی، فونت وزیرمتن):

- **مدیریت پرسنل** — مشخصات، حقوق پایه ماهانه، سمت و بخش
- **برنامه کاری (شیفت)** — تعریف ساعت کاری جداگانه برای هر روز هفتهِ هر نفر
- **تردد** — ثبت ورود، **خروج موقت بین تایم کاری** (با ثبت بازگشت)، خروج نهایی، ورود مجدد و ثبت دستی اصلاحی
- **مرخصی** — روزانه (با حقوق) و ساعتی
- **حقوق و فیش** — حقوق کسب‌شده متناسب با زمان کارکرد واقعی هر روز، اضافه‌کاری، پاداش، کسورات و ثبت پرداخت‌های علی‌الحساب؛ صدور و چاپ فیش
- **گزارش‌ها** — ماتریس حضور نفر-به-روز، خروجی اکسل (CSV) و چاپ
- **تنظیمات** — مبنای نرخ روزانه/ساعتی، ضریب اضافه‌کاری، فرصت ارفاق و بازنشانی داده نمونه

تکنولوژی: Next.js 16 + PostgreSQL (Drizzle ORM) + Tailwind CSS 4

## نسخه‌بندی نرم‌افزار

شماره نسخه فقط در فیلد `version` فایل `package.json` نگهداری می‌شود؛ رابط برنامه و بسته‌بندی ویندوز از همین مقدار استفاده می‌کنند.

قالب نسخه‌بندی: `MAJOR.MINOR.PATCH`

- `npm run version:patch` — رفع باگ و اصلاحات کوچک (مثلاً 1.2.0 به 1.2.1)
- `npm run version:minor` — افزودن قابلیت سازگار جدید (مثلاً 1.2.0 به 1.3.0)
- `npm run version:major` — تغییرات بزرگ و ناسازگار (مثلاً 1.2.0 به 2.0.0)

این فرمان‌ها نسخه را افزایش می‌دهند و commit و tag نسخه می‌سازند. سپس با `git push && git push --follow-tags` تغییرات و تگ را ارسال کنید تا GitHub Actions بیلد ویندوز را انجام دهد. برای تغییرات روزمره، تا زمان آماده‌شدن یک انتشار، نسخه را افزایش ندهید؛ هر انتشار قابل نصب باید یک شماره نسخه مشخص داشته باشد.

## ۱) اجرا به‌صورت وب (سرور یا سیستم شخصی)

پیش‌نیاز: Node.js 20+ و PostgreSQL

```bash
npm install
cp .env.example .env        # آدرس دیتابیس را داخل .env تنظیم کنید
npx drizzle-kit push        # ساخت جداول دیتابیس
npm run dev                 # اجرای توسعه روی http://localhost:3000
# یا برای پروداکشن:
npm run build && npm start
```

با اولین اجرا، داده‌های نمونه (۸ پرسنل + ۴۵ روز تردد + فیش) به‌صورت خودکار ساخته می‌شود؛
از صفحه «تنظیمات» می‌توانید آن را بازنشانی کنید. چون اپ وب است، اگر روی یک سیستم/سرور داخلی اجرا شود،
همه نفرات می‌توانند هم‌زمان با مرورگر موبایل یا کامپیوتر به آن وصل شوند.

## ۲) گرفتن خروجی EXE ویندوز با GitHub Actions

این مخزن یک workflow آماده دارد: `.github/workflows/build-exe.yml`
کافی است پروژه را روی گیت‌هاب بگذارید:

```bash
git init
git add .
git add package-lock.json   # مهم: لاک‌فایل باید کامیت شود (بیلد پایدار)
git commit -m "Vaqtban HR suite"
git branch -M main
git remote add origin https://github.com/<YOUR-USER>/<YOUR-REPO>.git
git push -u origin main
```

> اگر فراموش کنید `package-lock.json` را کامیت کنید هم ورکفلو به‌صورت خودکار آن را می‌سازد،
> ولی برای بیلدهای پایدار و قابل‌تکرار حتماً آن را در مخزن نگه دارید.
> (اگر با رابط وب گیت‌هاب آپلود می‌کنید، مراقب باشید این فایل جا نماند.)

### رفع خطاهای رایج ورکفلو

ورکفلو در برابر ناقص‌بودن مخزن «خودترمیم‌گر» است، ولی ریشه‌ی بیشتر خطاها یکی است:
موقع آپلود، بعضی فایل‌ها و پوشه‌ها در گیت کامیت نشده‌اند. این‌ها باید در مخزن باشند:

| فایل/پوشه | اگر نباشد چه می‌شود؟ |
|---|---|
| `package-lock.json` | ورکفلو خودش می‌سازد، ولی بهتر است کامیت شود |
| `public/` (فونت‌ها) | ورکفلو از روی `node_modules` بازیابی می‌کند |
| `build/icon.png` | آیکون پیش‌فرض Electron جایگزین می‌شود |
| `electron/`, `electron-builder.yml`, `src/` | حیاتی‌اند — بدون آن‌ها بیلد متوقف می‌شود |

ساده‌ترین راه برای کامیت صحیح همه‌چیز:

```bash
git add -A            # همه‌ی فایل‌ها و پوشه‌ها، بدون استثنا
git status            # نگاه کن public/ و build/ و .github در لیست باشند
git commit -m "add missing project files"
git push
```

سپس یکی از این دو کار را انجام دهید:

**الف) اجرای دستی (پیشنهادی اول):**
1. در گیت‌هاب وارد تب **Actions** مخزن شوید
2. ورکفلوی **Build Windows EXE** را انتخاب کنید
3. روی دکمه **Run workflow** بزنید
4. بعد از اتمام (حدود ۵ تا ۸ دقیقه)، از بخش **Artifacts** 
   فایل `vaqtban-windows` را دانلود کنید — داخلش دو فایل exe است:
   - `Vaqtban Setup 1.2.0.exe` → نصب‌کننده ویندوز (با شورتکات دسکتاپ)
   - `Vaqtban 1.2.0.exe` (پرتابل) → نسخه بدون نصب
   (نام دقیق فایل‌ها را در زیپ آرتیفکت می‌بینید.)

**ب) خروجی خودکار با هر نسخه جدید:**

```bash
git tag v1.2.0
git push origin v1.2.0
```

> نکته: خروجی امضای دیجیتال ندارد؛ ویندوز ممکن است هشدار SmartScreen بدهد 
> (Run anyway). اگر خواهید، گواهی امضا را در Action اضافه کنید.

### نسخه دسکتاپ چطور کار می‌کند؟
نسخه دسکتاپ **کاملاً خودکفا** است — با **دیتابیس PostgreSQL جاسازی‌شده (PGlite)** کار می‌کند.
یعنی: نصب ← اجرا ← شروع کار. هیچ نصب اضافه‌ای لازم نیست.

- داده‌ها در `%APPDATA%/vaqtban-desktop/pgdata/` ذخیره می‌شوند و داخل پوشه نصب برنامه نیستند.
- نصب نسخه جدید با همان شناسه برنامه (`com.vaqtban.desktop`) روی مسیر نصب قبلی انجام می‌شود؛ در نصب‌کننده مسیر قبلی را انتخاب کنید.
- حذف برنامه یا نصب نسخه جدید، فایل‌های دیتابیس را پاک نمی‌کند (`deleteAppDataOnUninstall: false`).
- پیش از هر بار اجرای نسخه دسکتاپ، از دیتابیس داخلی یک نسخه پشتیبان در `%APPDATA%/vaqtban-desktop/db-backups/` ساخته می‌شود؛ ۱۰ نسخه آخر نگهداری می‌شوند.
- اطلاعات تردد و حقوق با تغییر ماه حذف نمی‌شوند. از فلش‌های انتخاب ماه در صفحات «گزارش‌ها» و «حقوق و فیش حقوقی» برای مشاهده ماه‌های گذشته استفاده کنید.
- بازنشانی «داده‌های نمونه» یک عملیات دستی و مخرب است و فقط با تأیید کاربر انجام می‌شود؛ در استفاده واقعی آن را انتخاب نکنید.

اگر خواهید چند کامپیوتر به یک دیتابیس مشترک وصل شوند، فایل زیر را باز کنید
و آدرس PostgreSQL سرور را داخل آن بنویسید، سپس برنامه را دوباره اجرا کنید:

```
%APPDATA%/vaqtban-desktop/config.env    ←  DATABASE_URL=postgresql://user:pass@server:5432/db
```

## ۳) قواعد محاسبه حقوق (قابل تغییر در صفحه تنظیمات)

| قاعده | فرمول |
|---|---|
| نرخ روزانه | حقوق پایه ماهانه ÷ روزهای مبنا (پیش‌فرض ۳۰) |
| حقوق روزانه کسب‌شده | نرخ روزانه × نسبت کارکرد خالص به زمان موظفی همان روز؛ شیفت کامل = یک روز کامل، نیم‌شیفت = نصف روز |
| حقوق ماهانه کسب‌شده | مجموع حقوق روزانه کسب‌شده در روزهای حضور + مرخصی روزانه باحقوق |
| نرخ ساعتی اضافه‌کاری | حقوق پایه ماهانه ÷ ساعات موظفی ماه (پیش‌فرض ۲۲۰) |
| اضافه‌کاری | نرخ ساعتی × ضریب (پیش‌فرض ۱۴۰٪) × ساعت مازاد بر موظفی |
| پرداخت علی‌الحساب | هر پرداخت با مبلغ، عنوان و تاریخ واقعی ثبت می‌شود و از مانده قابل پرداخت همان ماه کم می‌شود |

غیبت و زمان کارنکرده از ابتدا حقوقی ایجاد نمی‌کنند؛ بنابراین دوباره به‌عنوان کسری از حقوق کامل ماه کم نمی‌شوند. مرخصی روزانه باحقوق، یک روز کامل محسوب می‌شود و مرخصی بدون حقوق، حقوقی ایجاد نمی‌کند. مرخصی ساعتی باحقوق نیز در زمان قابل پرداخت همان روز لحاظ می‌شود. کارکرد در روز تعطیل، برای پرسنل مشمول اضافه‌کاری، طبق قاعده اضافه‌کاری محاسبه می‌شود.
